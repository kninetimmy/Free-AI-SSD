================================================================================
 Free-AI-SSD — Quickstart
 Portable offline AI on an SSD. Prepare once online, run anywhere offline.
================================================================================

--------------------------------------------------------------------------------
 Quick Start in 5 Steps (the impatient version)
--------------------------------------------------------------------------------

1) Plug in a portable SSD. Pick a target compatibility — see the
   source/target matrix below for which OS to prep from for which
   target filesystem.
2) On a Windows OR Mac machine with internet, download the latest ZIP
   from GitHub Releases and extract it:
     - Stable:       Free-AI-SSD-win.zip               (Windows target only)
     - Beta (xplat): Free-AI-SSD-crossplatform.zip     (Windows + macOS,
                                                        includes Mac PrepApp)
   The extracted root is minimal: the prep tool(s), LICENSE, QUICKSTART,
   and one dependencies/ folder (runner / companion / prereqs / mac).
   Cross-platform: prep the macOS side from a Mac (PrepApp.app) — Windows
   archivers strip the symlinks inside macOS .app bundles.
3) Run the prep tool for your host OS:
     - Windows host: FreeAiSsd.PrepApp.exe
     - Mac host:     PrepApp.app  (from the cross-platform bundle)
   *** Mac users: the current beta is unsigned, so Gatekeeper will say
       "FreeAiSsd is damaged and can't be opened" the first time. Run
       once in Terminal to unblock, then double-click as normal:
         xattr -dr com.apple.quarantine /path/to/PrepApp.app
         xattr -dr com.apple.quarantine /path/to/Runner.app
       This goes away with the next signed release. See "macOS first
       launch" below for details.  ***
   Select your SSD. Choose target compatibility (Windows-only / Mac-only
   / cross-platform). On the "Set up the drive" step, pick how you'll
   reach the assistant: "This device only" (encryption optional) or
   "Other devices on my LAN" (encryption required — see "API key & LAN
   access" below). Format the drive (the prep tool picks the right
   filesystem from your target choice — see matrix below). Pull one
   model (e.g. phi3 or llama3.1:8b). Run readiness checks, then finalize.
   If you chose LAN, the final screen shows your API key with a Copy
   button.
4) Unplug. Plug into the machine you actually want to use it on.
     - Windows: <SSD>\windows\runner\FreeAiSsd.Runner.exe
     - macOS:   <SSD>/Runner.app    (at the drive root; beta bundle only;
                unsigned, limited Runner API sidecar)
5) Start the AI engine in Runner and chat. On Windows, the full Runner
   supports RAG, citations, voice, HOTAS/PTT, DCS import, and Network
   Mode. The macOS beta supports RAG-backed chat against an already
   prepared active library, but not Mac-side document management yet.

--------------------------------------------------------------------------------
 Source / Target Compatibility Matrix
--------------------------------------------------------------------------------

 Which prep host (source OS) can produce which target drive:

 +-----------+----------------+------------+----------------------------------+
 | Source OS | Target         | Filesystem | Supported?                       |
 +-----------+----------------+------------+----------------------------------+
 | Windows   | Windows-only   | NTFS       | Yes                              |
 | Windows   | Cross-platform | exFAT      | Yes                              |
 | Windows   | Mac-only       | exFAT      | Yes (APFS not available from     |
 |           |                |            |   Windows)                       |
 | Mac       | Mac-only       | exFAT      | Yes (APFS deferred from current  |
 |           |                |            |   supported targets)             |
 | Mac       | Cross-platform | exFAT      | Yes                              |
 | Mac       | Windows-only   | NTFS       | Not supported — use Windows      |
 |           |                |            |   PrepApp (macOS cannot natively |
 |           |                |            |   format NTFS)                   |
 +-----------+----------------+------------+----------------------------------+

 Encryption is driven by the access choice on the "Set up the drive"
 step. "This device only" leaves encryption optional (off by default;
 turn it on to protect your config + any saved Hugging Face token at
 rest). "Other devices on my LAN" requires encryption and turns it on
 for you, because your LAN API key is only ever stored encrypted —
 PrepApp confirms this before switching. Either way you choose the
 unlock passphrase at the final step, and the Runner asks for it on
 each launch. Plaintext-prepped SSDs roundtrip cleanly between OSes.
 The on-disk encrypted format (AES-256-GCM + PBKDF2-SHA256) is identical
 on both platforms when enabled.

 Notes:
 - APFS is a Mac-native filesystem; Windows cannot reliably create or
   write to it. APFS targets are deferred from the supported set; exFAT
   covers all Mac use today.
 - exFAT is the only filesystem Windows and macOS both read and write
   natively, so cross-platform drives always land on exFAT.
 - The "Mac → Windows-only NTFS" cell is an OS limitation, not a
   project gap. Use Windows PrepApp if you need an NTFS-only drive.

Everything below is optional and layered on top of that baseline.

--------------------------------------------------------------------------------
 What You Need
--------------------------------------------------------------------------------

- A portable SSD. Budget ~5–10 GB per LLM, plus headroom for documents and
  Whisper STT models. A 128 GB drive is comfortable; 64 GB is the practical
  minimum.
- A Windows OR Mac machine with internet for the one-time preparation.
  PrepApp ships for both: FreeAiSsd.PrepApp.exe on Windows, PrepApp.app
  (in the cross-platform bundle) on macOS. Pick whichever host you have
  — see the Source/Target matrix above for which target filesystems each
  host can produce.
- Windows target machines need no pre-installed software. Windows Runner
  carries its own prerequisites. The macOS beta bundle stages macOS Ollama,
  plus the local API sidecar for RAG-backed chat.
- Target OS: Windows 10/11 x64 for the full Runner, or macOS beta for
  limited sidecar-backed chat.
- Mac host requirements: Apple Silicon (arm64) only; macOS 11 Big Sur
  or newer. Intel Macs are not supported.

--------------------------------------------------------------------------------
 Full Feature Setup
--------------------------------------------------------------------------------

 1. Offline AI on a Portable SSD (the core)
 ------------------------------------------
 Already covered in the 5-step quick start. A few notes:

 - Filesystem is picked by your target compatibility choice (see the
   Source/Target matrix above):
     Windows-only target  -> NTFS  (Windows host only)
     Cross-platform / Mac -> exFAT (either host)
   On Windows, PrepApp's "Format & Prepare Drive" formats per that
   choice (requires admin; PrepApp relaunches elevated and auto-resumes
   your selection + label, then asks once more before wiping). On Mac,
   PrepApp.app uses `diskutil` with explicit confirmation through a
   native NSAlert before erasing the drive.
 - APFS is deferred — exFAT is the supported Mac target today. NTFS-only
   drives must be prepped from Windows; macOS cannot natively format NTFS.
 - Ollama is staged onto the SSD by PrepApp and bound to loopback only
   (127.0.0.1). No network surface by default.
 - Models live at <SSD>/models/. Pull more any time via PrepApp's Model
   Manager; this is the only step that requires internet.
 - Runner auto-installs any missing Windows prerequisites (VC++ redist,
   .NET 8 Desktop Runtime) from the staged offline bundle on first run.

 - macOS beta scope: <SSD>/Runner.app can select/infer the SSD, unlock
   encrypted Windows-prepped SSDs (MAC5 native CryptoKit port), read installed
   models, start <SSD>/mac/tools/ollama/ollama, host the Runner API sidecar,
   and send RAG-backed chat with citations against an already prepared active
   library. It does not currently support Mac-side document library
   management, ingestion/rebuild/sweep, voice/TTS, HOTAS/PTT, or DCS import UI.

 2. Windows Runner: RAG Document Library (grounded answers from your own files)
 -----------------------------------------------------------------------------
 Load PDFs, manuals, and notes so the AI answers from your documents
 instead of guessing.

 - In Windows Runner, open the "Reference Documents" panel.
 - Create or select a library.
 - "Add files" to pull in specific documents, or "Add folder" to watch a
   folder and auto-ingest new files.
 - Click "Sweep folders now" to ingest, or "Rebuild index" to re-embed
   everything.
 - Supported formats: .pdf, .txt, .md, .json, .csv. DOCX is not supported.
 - PDFs must have an embedded text layer. Scan-only PDFs need OCR first.
 - Answers cite sources inline, e.g. [manual.pdf p.12]. If nothing in the
   library meets the similarity threshold, the model is explicitly told
   "no relevant documents found" rather than hallucinating.
 - First use of RAG needs the embedding model (nomic-embed-text). Pull it
   once online via Windows Runner's "Pull embedding model" button.

 3. Windows Runner: DCS Bindings Parser (HOTAS-aware answers)
 -----------------------------------------------------------
 Import your DCS World controller bindings so the AI answers with the
 buttons on *your* stick and throttle.

 - In Windows Runner, open "Bindings Import" (requires an active document library).
 - Windows Runner auto-detects your Saved Games\DCS and Saved Games\DCS.openbeta
   folders. If it doesn't find them, browse manually.
 - Click "Scan" — every aircraft with binding files in Config/Input is
   listed.
 - Select aircraft and click "Import". Windows Runner reads each device's
   diff.lua (stick, throttle, rudder pedals), merges them per-aircraft,
   and writes a reference document into your library.
 - Rebuild the index (or wait for the next folder sweep).

 Supported: DCS World stable and Open Beta, multi-device merging.
 Not yet supported: IL-2 Sturmovik, War Thunder.

 4. Windows Runner: Voice Input — Whisper.cpp STT
 -----------------------------------------------
 Speak your questions. Transcription is fully local via Whisper.cpp.

 - Click the microphone button in Windows Runner to start/stop recording.
 - Transcription runs locally; text is either sent automatically or placed
   in the prompt for review (controlled by autoSendVoiceInput in config).
 - Whisper model sizes live at <SSD>/models/whisper/:
       Tiny   ~75 MB    fastest, lower accuracy
       Base  ~142 MB    default, good for most use
       Small ~466 MB    better accuracy
       Medium ~1.5 GB   best accuracy, more RAM
 - First voice use downloads the selected model (one-time internet step).
   After that, fully offline.

 5. Windows Runner: Voice Output — TTS
 ------------------------------------
 Have the AI speak back.

 - Enable TTS in settings. Two engines:
     System — Windows SAPI; built-in, no downloads required.
     Piper  — neural TTS; better quality. Drop piper.exe and a voice
              model into <SSD>/windows/tools/piper/.
 - Route TTS to a specific output device (e.g. your VR headset) so AI
   speech and system audio can go to different places.
 - TTS is offline regardless of engine.

 6. Windows Runner: HOTAS Push-to-Talk (hands-free voice, for VR)
 ---------------------------------------------------------------
 Bind a joystick button to start/stop voice recording. No keyboard,
 no headset removal, no hands off the controls.

 - In settings, enable PTT and pick your device (e.g. "X-56 Rhino
   Throttle").
 - Set the button index.
 - Pick a mode:
     push_to_talk — hold the button to record, release to send
     toggle       — press once to start, press again to stop and send
 - Optional: always-on-top status overlay (disable for VR), and an
   activation beep.
 - Full loop: button -> mic opens -> speak -> release -> Whisper
   transcribes -> prompt sent -> AI responds -> TTS plays through your
   chosen output device.

 7. Windows Runner: (Optional) Network Mode — run on one PC, query from another
 ----------------------------------------------------------------------------
 One Windows machine runs Runner + Ollama. Other devices on the same LAN call
 Runner's HTTP API for chat, STT upload, and host-side TTS.

 - Ollama stays loopback-only. LAN clients talk to the Runner API,
   never to Ollama directly.
 - Default bind is 127.0.0.1; 0.0.0.0 is an explicit opt-in in
   portable-config.json (Runner logs a warning when not loopback).
 - API key auth required on non-health endpoints.
 - Endpoints: /api/health, /api/models, /api/chat, /api/chat/stream,
   /api/stt/transcribe, /api/voice/query, /api/tts/speak, /api/tts/stop.
 - Do not expose this API to the public internet.

 8. Web Chat UI — query from a browser (incl. iPad over LAN)
 ----------------------------------------------------------
 An install-free chat client served straight from the Runner's LAN API.
 Open it in any browser — the host machine or another device on your LAN
 — for the full assistant experience minus voice.

 - Requires Network Mode (section 7): the web UI is served by the same
   Runner API, so Start Ollama and enable Network Mode first.
 - On the host machine: click "Open Chat UI (browser)" in Runner, or
   browse to http://127.0.0.1:41555/chat/.
 - From another LAN device (e.g. an iPad on the sim rig):
     1. Set networkBindAddress to 0.0.0.0 in portable-config.json and
        restart Runner (same opt-in as Network Mode above).
     2. Allow inbound TCP 41555 through the host firewall.
     3. Browse to http://<host-LAN-IP>:41555/chat/ (or
        http://<hostname>.local:41555/chat/).
     4. Enter the API key once when prompted — it's saved per-device in
        the browser (localStorage), along with your chat history.
 - What you get: model picker, active document-library picker, basic
   params (temperature/thinking), streaming answers with a collapsible
   "Thinking..." view and a Sources panel, and RAG against any prepared
   library. Voice (STT/TTS/PTT) stays native-only.
 - Cross-platform: the same UI is served by the Windows Runner and the
   macOS beta sidecar — nothing extra to install on the client device.
 - Plain HTTP, trusted-home-LAN only, API-key gated. Do not expose it to
   the public internet; there is no TLS.
 - Port note: 41555 is the default; if it's busy Runner picks the next
   free port and logs "Network API started at http://...". The in-app
   "Open Chat UI" button always targets the right one.

 9. API key & LAN access — step by step
 --------------------------------------
 The API key is the shared secret that lets other devices reach the
 Runner over your LAN. You never invent it — it's generated for you.
 Here's the whole lifecycle so there's no guesswork.

 What it is
   - A random 256-bit key created automatically the first time you
     finalize an SSD. It's stored ONLY in the drive's encrypted config,
     which is why LAN access requires encryption.
   - It is not a cloud account, login, or anything you sign up for.
     Everything stays on your drive and your LAN.

 During prep (one time)
   1. On the "Set up the drive" step, choose "Other devices on my LAN".
      PrepApp confirms that the drive must be encrypted and turns
      encryption on.
   2. Finish pulling models and click "Finish setup". You'll set the
      unlock passphrase here.
   3. On the final "Drive ready" screen, your API key is shown with a
      Copy button. Copy it now (or come back for it later — see below).

 On the host PC (the machine that runs Runner)
   1. Launch the Runner from the SSD and unlock it with your passphrase.
   2. Start the AI engine, then open Settings -> Network Mode.
   3. Tick "Enable Network Mode" and choose "Other devices on my LAN
      (0.0.0.0)". (This radio is only available on an encrypted drive.)
      "Require API key" is forced on for LAN.
   4. The key is shown in the API key box. Use "Copy" to grab it, or
      "Generate" to roll a new one (every device then has to re-enter
      the new value).
   5. Allow inbound TCP 41555 through the host's firewall the first time
      Windows asks.

 On each other device (iPad, laptop, second PC)
   1. Open a browser and go to http://<host-LAN-IP>:41555/chat/
      (or http://<hostname>.local:41555/chat/). Find the host IP from
      Runner's Network Mode status line, or your router.
   2. The web UI prompts for the API key on first use. Paste it once.
      It's saved in that browser (localStorage) along with your chat
      history, so you won't be asked again on that device.
   3. The Companion app (VR/split-PC setups) takes the same key in its
      Settings, or reads it from companion-config.json staged on the SSD.

 Lost or rotating the key
   - Forgot to copy it? Open Runner -> Settings -> Network Mode ->
     Copy. (You must unlock the drive first; the key lives in the
     encrypted config.)
   - Suspect it leaked, or just want a fresh one? Click "Generate" in
     Network Mode, then re-enter the new key on every device. Old
     values stop working immediately.

 Safety
   - Plain HTTP, no TLS — trusted home LAN only. Anyone who has the key
     AND can reach port 41555 can use your assistant. Never forward the
     port or expose it to the public internet.

--------------------------------------------------------------------------------
 Use Cases
--------------------------------------------------------------------------------

 Ham Radio / Field Reference
   You're deployed for emergency comms or camping with no cell signal.
   Load radio manuals, band plans, and reference docs onto the SSD
   before you leave. On Windows Runner, ask by voice and get cited
   answers. On the macOS beta, use RAG-backed chat against an already
   prepared active library.

 DCS / Flight Sim VR Copilot
   You're in VR, mid-sortie. You forget how to uncage an AIM-9 on the
   F-16C. In the Windows Runner, press the PTT button on your throttle,
   ask, and hear the answer spoken back using *your* actual HOTAS
   bindings and the real aircraft manual. Hands never leave the stick,
   headset never comes off, and no cloud AI is involved.

 Private Offline AI Assistant
   You don't trust cloud AI with your data, your workplace restricts
   internet, or you just want the same staged SSD available across your
   machines. Windows Runner is the full offline assistant; macOS is the
   current direct-chat beta.

 Survival / Emergency Reference
   First-aid guides, plant identification, equipment manuals, survival
   references — whatever you need when you're off-grid.

--------------------------------------------------------------------------------
 Troubleshooting
--------------------------------------------------------------------------------

 Runner won't start / dependency warnings
   Use Runner's "Re-run dependency check". If the staged prereq bundle
   is missing or invalid, plug the SSD back into an online machine and
   run "Update Prereqs" in PrepApp.

 "Pull embedding model" required
   The RAG pipeline needs nomic-embed-text. If the SSD doesn't have it
   yet, Runner prompts to pull it. Online once, offline forever after.

 PDF citations seem wrong or sparse
   The PDF probably has no text layer (scanned image). Run OCR on it
   externally, then re-ingest.

 No mic input / Whisper hears nothing
   Check selectedMicrophoneDevice in portable-config.json. Unset (null)
   means "system default". Confirm the mic is actually selected at the
   OS level too.

 PTT button does nothing
   Confirm the device name in pttDeviceName exactly matches what
   DirectInput reports (Runner logs the detected devices at startup).
   Check pttButtonIndex — it's zero-based.

 TTS plays on the wrong speakers
   Set ttsOutputDevice to the exact device name. Useful for sending AI
   voice to your VR headset while keeping system audio on desktop
   speakers.

 macOS: "FreeAiSsd is damaged" / Gatekeeper blocks the app
   The beta macOS apps are unsigned / not notarized, so when Safari
   downloads the ZIP it stamps the .app bundles with a quarantine
   xattr. The combination of "ad-hoc signature" + "quarantine bit"
   makes Gatekeeper claim the bundle is *damaged* even though it is
   not — right-click -> Open and "Allow apps from anywhere" do not
   help in this state.

   The fix is to strip the quarantine xattr once. Open Terminal and
   run, replacing the path with where you extracted the bundle:
     xattr -dr com.apple.quarantine /path/to/PrepApp.app
     xattr -dr com.apple.quarantine /path/to/Runner.app
   After that both apps double-click open like any other. This step
   goes away with the next signed/notarized release.

 macOS: document management and voice features are missing
   Expected in the current beta. The Swift runner is not yet a full Windows
   Runner equivalent. It provides encrypted SSD unlock, Network Mode hosting,
   and RAG-backed chat against an existing active library. Use the Windows
   Runner for document library management, Mac-side ingestion/rebuild/sweep,
   voice/TTS, HOTAS/PTT, and DCS bindings import.

 Network Mode clients can't connect
   By default Runner binds to 127.0.0.1. To accept LAN connections,
   set networkBindAddress to 0.0.0.0 in portable-config.json and
   restart Runner. Firewall rules on the host still apply.

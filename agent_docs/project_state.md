- **PR #197 — MAC17a PrepHostController cancel/leak fixes from PR #195 review — merged `0b18809` (2026-05-07).** Closes out the four Gemini review comments on PR #195. **Fix 1 (HIGH)** — `awaitCommandResult` registration silently dropped the continuation when `weakSelf` was nil (still flipped `didRegister = true`, fired `dispatch()`, and left `withCheckedThrowingContinuation` suspended forever → `CheckedContinuation` runtime trap on dealloc). Added explicit `else if let strong` / `else { cont.resume(throwing: .notRunning) }` chain. The path is structurally unreachable from outside today (call site retains strong self for the entire `awaitCommandResult` duration), but defensive against future refactors. **Fix 2/3 (HIGH)** — `try?` swallowed `Task.sleep`'s `CancellationError`, so a cancelled `Task { await vm.finalize() }` would spin both `shutdown()` poll loops until their deadlines (~2.5s of CPU). The `terminationHandler` captures `[weak self]` so it no-ops once self is gone, leaving any in-flight `pendingResults` continuations stranded → `CheckedContinuation` traps on its own dealloc. Added `failAllPending(.notRunning)` to deinit; safe because `failAllPending` uses `stateQueue.sync` (no actor isolation, no async). New `failAllPendingForTest` internal seam mirrors the existing `pendingResultsCountForTest` pattern; new "Fix 4: failAllPending drains pending continuations" test pins the deinit drain behavior by registering a continuation via `awaitCommandResult`, calling the seam, and asserting the awaiting Task resumes with `.notRunning`. Notable lesson captured: when both lifetime-driven and cancellation-driven `CheckedContinuation` paths exist, every leaf needs an explicit resume — the type system permits silent drops that don't surface until dealloc traps in production.

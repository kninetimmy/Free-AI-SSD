## Recently shipped

- **PR #247 — C2 PrepApp auto-pulls embedding model + harden ingest failure surface — merged `1df4431` (2026-05-10).** No new release tag (bug fix folds into next ship). Closes the v1.3.22 mac field-test 100%-embed-failure pathology that MAC35 explicitly deferred ("Filed as a follow-up if the embedding-pull pathology actually surfaces in the field"). **Root cause:** `PortableConfig.EmbeddingModelName` defaults to `"nomic-embed-text"` but PrepApp's F2a picker is chat-only and the bundled `starter-models.json` has no embedding entry — freshly-prepped SSDs reached first ingest with no embedder on disk, every `/api/embed` chunk-call 404'd, and `DocumentIngestor`'s blanket `catch (Exception)` discarded the cause so the user saw only `embedding failures exceeded threshold (ratio=100%)`. **Stage 1 fix:** new `PrepViewModel.EnsureEmbeddingModelInstalledAsync` helper does an idempotent disk-truth check (normalizes Ollama's `name` ↔ `name:latest` equivalence) and pulls when missing. Wired into two call sites — (1) `DownloadAsync` tail, reusing the temp Ollama server already running for the chat-model loop so the embed pull costs no extra startup; (2) `EnsureEmbeddingModelOnFinalizeAsync` guard inside `FinalizeAsync`, which spins its own server only when the disk-check shows the embedder is missing, so re-finalize on a fully-prepped drive is free. Best-effort: failed pull logs but does not abort finalize — offline users still need to be able to ship without RAG, and Stage 2 makes the runtime error self-explanatory if they later try to ingest. **Stage 2 diagnostic hardening:** `EmbeddingClient.EmbedAsync` replaced `EnsureSuccessStatusCode` with explicit body-reading throw (mirrors MAC40's `OllamaPullClient` pattern) — the `/api/embed` 404 body `{"error":"model 'X' not found"}` now surfaces in the exception with the body trimmed/snippetted and `HttpRequestException.StatusCode` set. `DocumentIngestor` adds `Exception? firstFailure` outside the per-chunk lambda; `Interlocked.CompareExchange(ref firstFailure, ex, null)` in the catch captures the first failure thread-safely, and the threshold abort message gains a `" First failure: {firstFailure.Message}"` suffix. Both `IngestFiles` and `RebuildIndex` paths covered. **Cross-OS:** shared `prep-core` + `shared/Documents` — Windows + Mac PrepApp pick up the fix in one bundle. No `mac-prep-host` wire-protocol change (the embed pull is just another `ModelOperations.PullModelAsync` against the existing temp server). MAC35's stage-then-merge applies transparently on Mac (the 270 MB single-layer embedder is small enough that staging overhead doesn't matter). Mac-runner UI defense-in-depth (mirror of Windows runner's `PullEmbeddingModel_Click`) deferred to **M14** per the parity rule — it reopens MAC35-deferred questions about pulling against the live daemon. **Tests (8 new pins):** 4 PrepViewModel (Download pulls embed when missing, skips when on disk; Finalize same), 1 DocumentIngestor (threshold message includes first-failure cause), 3 EmbeddingClient (404 body + StatusCode, 500 empty-body, 200 happy path). **CI required a second push** — first run green on mac jobs (which don't run `dotnet test`) but failed Windows on 2 of the new Download tests with `NullReferenceException` in `ConfirmSizingWarningsIfNeeded`: `_modelService.BuildPullSelectionWarnings` returns null by Moq default, and the existing `DownloadCommand_CheckedRowsAlreadyOnDrive_SkipsPull` short-circuits before reaching that line. Test-only fix (`e008ac2`) added the mock to my two new tests; production code unchanged. Second pass green on all three jobs (mac-prep 45s, mac-runner 52s, windows 3m19s).

- **PR #241 — MAC40 pull progress source-of-truth switches to Ollama HTTP /api/pull NDJSON — merged `b5ac727` (2026-05-10).** Released as **v1.3.21**. Closes the v1.3.20 mac field-test pull-progress regression where the in-place label stopped updating and every progress tick scrolled past as a log line. Root cause: `OllamaPullProgressFilter.IsProgressLine`'s regex anchored on `pulling <hash>... NN%` with literal dots; MAC38's dynamic Ollama version resolution brought in upstream releases that shifted the TUI to `pulling <hash>: NN%` with a colon, so every frame failed the match and routed to the scrolling log channel. **Smart fix, not minimal fix:** retire the CLI-stdout parser entirely and consume the canonical contract — `POST /api/pull` returns streaming NDJSON of structured frames (`status` / `digest` / `total` / `completed`). The temp Ollama server is already running and `OLLAMA_HOST` is already plumbed through `PullModelAsync(...ollamaHost...)` from MAC27, so the swap is local to `prep-core/`. New `OllamaPullClient.PullAsync(host, tag, onProgress, ct, handler?)` streams NDJSON, surfaces non-2xx response bodies in the exception (so MAC38-style "412 requires newer version" stays readable), tolerates throwing callbacks, has an `HttpMessageHandler` test seam, disables HttpClient's per-request timeout in favor of the caller's CT. New `OllamaPullProgress` record (`Status`, `Digest`, `Total`, `Completed`) with `ToDisplayString()` for both consumers — Mac sidecar formats via `progress => EmitProgress(progress.ToDisplayString())`; Windows VM uses the same shape through `SetPullProgressLineSafe`. `IModelService.PullModelAsync`'s onProgress signature changes from `Action<string>?` to `Action<OllamaPullProgress>?`, opening the door for MAC37 to render real progress bars from the structured fields. `ModelOperations.PullModelAsync` now requires `ollamaHost` (every production caller already passes it). `RunProcessStreamingAsync` + `Consume` lose their now-unused onProgress plumbing; only `DeleteModelAsync` still uses them. **Cancel/resume invariants preserved:** `pullCts.Cancel()` aborts the HttpClient call; partial blobs persist on disk; MAC31's `EstimatePartialProgress` seed is filesystem-based and untouched; MAC35 staging-then-merge flow on Mac is untouched (only the pull mechanism changes). **Cross-OS:** shared C# `ModelOperations` flips both platforms in one PR; the Mac sidecar's `progress: <text>` stdout channel is unchanged on the wire so `PrepHostController.swift` doesn't need a code change. **CI required a second push** — first run green on mac-prep + mac-runner but failed windows on `PrepViewModelTests.cs:751` (Moq.Verify expression with `It.IsAny<Action<string>?>()` as the seventh arg); commit `e9c68d8` flipped it to `It.IsAny<Action<OllamaPullProgress>?>()`.

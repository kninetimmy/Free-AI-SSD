# Project State

Last updated: 2026-05-08 (v1.3.6 cut + MAC25 shipped; v1.3.6 mac field test surfaced **MAC26** — a deeper architectural bug in how the Mac Ollama package is staged)

Last released: **v1.3.6** (2026-05-08; carries MAC25 OS-aware ollama filename on top of v1.3.5). v1.3.6 mac field test confirmed the resolver picks the bare `ollama` binary correctly — but exposed that the binary it picks is the wrong one. Both starter-model pulls failed; zero blobs landed on the SSD; sidecar hung 18 min after exit 137 (= SIGKILL) on qwen2.5:7b. Root cause is **MAC26**: the Mac Ollama distribution (`ollama-darwin.zip` v0.5.7) is a GUI desktop app, not a CLI server like Linux/Windows. The 119 KB binary the resolver finds is just an LSOpenURL shim — the real 53 MB self-contained Go server lives at `Ollama.app/Contents/Resources/ollama`. The shim hands off to LaunchServices, which strips env vars (`OLLAMA_MODELS` doesn't propagate to the spawned daemon), and headlessly-launched `Ollama.app` gets SIGKILL'd by macOS. User product call 2026-05-08 locked: don't require user-managed Ollama install — fix is to spawn the inner Resources/ollama directly as a sidecar child process (decision recorded in `project_decisions.md`).

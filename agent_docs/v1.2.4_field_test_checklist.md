# v1.2.4 field test checklist

Download the v1.2.4 artifacts from the dispatched workflow run
(https://github.com/kninetimmy/Free-AI-SSD/actions/runs/24618269649),
install from a fresh unzip onto the target SSD, and walk through each
section below. Record findings in a sibling `v1.2.4_field_test_findings.md`.

## What v1.2.4 changes (targets of testing)

1. **X1 — voice pipeline hang fix** (new). `PttVoicePipelineService`
   now awaits `StreamingTtsSpeaker.Completion` instead of polling
   `IsSpeaking` with a 60s timeout. Primary risk: voice pipeline
   regressions (TTS cut off, pipeline stuck in non-Idle state, or
   exceptions from the await path).
2. **Deferred verification #2 from v1.2.3** — B3-Redux UAC auto-resume
   hop against a real SSD. No code change since v1.2.3 cut, this is a
   real-hardware confirmation.

No other behavior change. X2 (ScrollViewer) and X3 (Start/Stop styles)
already shipped in v1.2.2/v1.2.3 — re-exercise briefly but they aren't
new in v1.2.4.

## Section 2 — X1 voice pipeline (primary change)

This is the main thing v1.2.4 is shipping. Run each case at least once.
Watch the "generating…" indicator; **it must clear within ~2s of audio
playback finishing**, not after a 60s pause.

### 2a. Happy path (short reply)

- [ ] Press PTT, speak a short question ("what time is it").
- [ ] Activation beep plays, deactivation beep plays on release.
- [ ] Transcription appears in the transcript pane.
- [ ] LLM response streams into the UI token-by-token.
- [ ] **TTS audibly speaks the full response to the end** — no
      mid-sentence cutoff.
- [ ] Immediately after the last word, indicator returns to Idle and
      you can press PTT again.
- [ ] **Fail mode to catch:** "generating…" sits for tens of seconds
      after audio stopped → the old polling path is back or the await
      isn't completing.

## Section 3 — Deferred verification #2: B3-Redux UAC auto-resume

This is the item that was deferred from v1.2.3 and never exercised on
real hardware. Run on a **physical external SSD**, not a VHD.

- [x] Launch PrepApp **non-elevated** (double-click, no admin).
- [x] Select the target SSD.
- [x] Enter a recognizable label (e.g., `FREEAI-TEST`).
- [x] Click "Format & Prepare Drive".
- [x] **UAC prompt appears** — accept.
- [x] Elevated PrepApp relaunches.
- [x] **Auto-resume banner** visible on the relaunched window.
- [x] Label field is **auto-filled** with what you typed pre-UAC.
- [x] Drive dropdown is **pre-selected** to the same drive.
- [x] Confirm dialog appears requiring explicit re-confirmation.
- [x] Accept confirm; format proceeds.
- [x] Format completes without error.
- [x] **Label on the physical drive matches what you typed** (check
      in Windows Explorer — the drive entry shows the new label).
- [x] Elevated window closes cleanly; no orphan process in Task
      Manager.
- [x] **Fail mode to catch:** auto-fill doesn't populate (banner
      shows but fields are blank) → `DriveFormatCommand.ParseDriveLetter`
      / `SanitizeLabel` dropped the args, should fall back to signpost
      banner, not crash.
- [x] **Fail mode to catch:** format runs *without* the confirm
      dialog → never-auto-format invariant broken, critical bug.

## Release decision

After all sections:

- **Ship v1.2.4 tag** if Sections 1, 2, and 3 are fully clean.
- **Defer tag** if X1 (Section 2) shows *any* hang regression —
  that's the whole point of the release.

  issue unrelated to X1/B3-Redux; file a new backlog item instead
  of blocking the tag.
